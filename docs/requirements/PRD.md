# 进销存管理系统产品需求文档（PRD）

## 1. 文档概述

### 1.1 文档目的
本文档详细描述了进销存管理系统的产品需求，包括核心功能、非功能需求、系统架构、数据需求、用户界面需求等，作为产品开发、测试和验收的依据。

### 1.2 文档范围
本文档涵盖了进销存管理系统的所有核心功能模块，包括采购管理、生产管理、库存管理、销售管理、财务管理和报表管理，以及系统的非功能需求、架构设计、数据设计和部署需求。

### 1.3 术语定义
| 术语 | 解释 |
|------|------|
| SKU | 库存单位（Stock Keeping Unit），用于唯一标识一个产品 |
| BOM | 物料清单（Bill of Materials），用于描述产品的组成结构 |
| FIFO | 先进先出（First In First Out），一种库存管理方法 |
| 批次 | 具有相同生产或采购时间、相同质量和特性的产品集合 |
| 周转率 | 库存周转的频率，计算公式：销售成本 / 平均库存 |
| 微服务 | 一种架构风格，将应用拆分为小型、独立的服务 |
| RESTful API | 基于REST原则设计的API |
| JWT | JSON Web Token，用于身份认证 |
| RBAC | 基于角色的访问控制 |

## 2. 产品介绍

### 2.1 产品背景
随着企业业务规模的扩大，传统的手工或简单的库存管理系统已经无法满足企业的需求。企业需要一个集成采购、生产、库存、销售和财务的一体化管理系统，以提高运营效率、降低成本、优化库存管理。

### 2.2 产品目标
- 实现企业进销存业务的一体化管理
- 提高库存管理效率，降低库存成本
- 优化采购和销售流程，提高业务响应速度
- 提供实时、准确的业务数据和报表
- 支持多部门协同工作
- 实现高可用、可扩展的系统架构

### 2.3 目标用户
- 企业管理人员
- 采购人员
- 生产人员
- 仓库管理人员
- 销售人员
- 财务人员
- 系统管理员

### 2.4 核心价值
- **提高效率**：自动化业务流程，减少手工操作
- **降低成本**：优化库存管理，减少库存积压和缺货
- **提升决策**：提供实时、准确的业务数据和分析报表
- **增强协同**：支持多部门协同工作，提高业务响应速度
- **保障安全**：完善的权限管理和数据安全机制

### 5.3 核心服务模块

#### 5.3.1 商品服务 (Product Service)
- 功能：管理商品目录、SKU、BOM等
- 主要接口：商品CRUD、SKU管理、BOM管理
- 依赖：PostgreSQL、Redis

#### 5.3.2 订单服务 (Order Service)
- 功能：处理订单创建、修改、查询、履行等
- 主要接口：订单CRUD、订单状态管理、订单履行
- 依赖：PostgreSQL、Redis、商品服务、库存服务

#### 5.3.3 库存服务 (Inventory Service)
- 功能：管理库存水平、库存移动、库存盘点等
- 主要接口：库存查询、库存更新、库存盘点
- 依赖：PostgreSQL、Redis

#### 5.3.4 销售服务 (Sales Service)
- 功能：处理销售订单、销售报表等
- 主要接口：销售订单管理、销售报表生成
- 依赖：PostgreSQL、Redis、订单服务

#### 5.3.5 采购服务 (Procurement Service)
- 功能：处理采购订单、采购计划等
- 主要接口：采购订单管理、采购计划生成
- 依赖：PostgreSQL、Redis、供应商服务

#### 5.3.6 客户服务 (Customer Service)
- 功能：管理客户信息、客户分类等
- 主要接口：客户CRUD、客户分类管理
- 依赖：PostgreSQL

#### 5.3.7 供应商服务 (Supplier Service)
- 功能：管理供应商信息、供应商分类等
- 主要接口：供应商CRUD、供应商分类管理
- 依赖：PostgreSQL

#### 5.3.8 认证服务 (Auth Service)
- 功能：处理用户认证、授权、令牌管理等
- 主要接口：登录、注册、令牌刷新、权限管理
- 依赖：PostgreSQL、Redis

#### 5.3.9 配置服务 (Config Service)
- 功能：管理系统配置、环境配置等
- 主要接口：配置CRUD、配置版本管理
- 依赖：Nacos Config

#### 5.3.10 API网关 (Gateway Service)
- 功能：处理API请求路由、负载均衡、安全认证等
- 主要接口：所有对外API接口的入口
- 依赖：Spring Cloud Gateway

### 5.4 共享模块

#### 5.4.1 公共模块 (Common)
- 功能：提供通用工具类、基础组件、统一异常处理等
- 主要组件：
  - ApiResponse：统一API响应格式
  - BusinessException：业务异常基类
  - GlobalExceptionHandler：全局异常处理器
  - Constants：常量定义
  - CustomCacheKeyGenerator：自定义缓存键生成器

## 6. 数据需求

### 6.1 数据库设计

#### 6.1.1 商品服务数据库
- 主要表：products、product_skus、boms、bom_components
- 关系：商品与SKU为一对多关系，商品与BOM为一对一关系，BOM与BOM组件为一对多关系

#### 6.1.2 订单服务数据库
- 主要表：orders、order_items、order_status_history
- 关系：订单与订单项为一对多关系，订单与订单状态历史为一对多关系

#### 6.1.3 库存服务数据库
- 主要表：inventory_levels、inventory_movements、inventory_audits
- 关系：库存水平与库存移动为一对多关系，库存水平与库存审计为一对多关系

### 6.2 缓存设计
- 使用Redis作为分布式缓存
- 缓存策略：
  - 商品信息缓存：30分钟
  - 库存水平缓存：5分钟
  - 订单信息缓存：10分钟
  - 用户会话缓存：30分钟
