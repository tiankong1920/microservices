# 代码审查清单

本文档定义了进销存管理系统的代码审查清单，确保所有代码提交都符合系统的质量标准和规范要求。

## 1. 技术架构

### 1.1 自动化检查工具集成
- [ ] Checkstyle检查通过，无违规项
- [ ] PMD检查通过，无违规项
- [ ] SpotBugs检查通过，无严重问题
- [ ] 代码覆盖率满足要求（>80%）
- [ ] 所有测试用例执行通过

### 1.2 组件设计
- [ ] 遵循系统现有的设计模式和架构原则
- [ ] 新增组件与现有组件保持一致的命名规范
- [ ] 代码结构清晰，职责单一
- [ ] 依赖关系合理，避免循环依赖

## 2. 审查清单

### 2.1 异常处理
- [ ] 所有业务逻辑都有适当的异常处理
- [ ] 使用系统定义的异常类型，而非RuntimeException
- [ ] 异常信息包含足够的上下文信息用于问题诊断
- [ ] 敏感信息不在异常信息中泄露
- [ ] 异常日志记录完整，包含必要字段
- [ ] 异常码使用规范，符合ExceptionCode枚举定义

### 2.2 API文档
- [ ] 所有对外暴露的API都有完整的Swagger文档
- [ ] API文档包含详细的参数说明和示例
- [ ] 错误响应格式符合ApiResponse规范
- [ ] API版本控制正确实现
- [ ] 请求和响应数据结构有清晰的描述

### 2.3 安全控制
- [ ] 所有API端点都有适当的安全注解（@PreAuthorize等）
- [ ] 敏感操作有权限控制
- [ ] 输入参数有验证，防止注入攻击
- [ ] 密码等敏感信息正确加密存储
- [ ] 日志记录中不包含敏感信息明文

### 2.4 代码质量
- [ ] 代码符合Java编码规范
- [ ] 命名规范一致且具有描述性
- [ ] 代码注释完整，特别是复杂业务逻辑
- [ ] 无重复代码（DRY原则）
- [ ] 代码复杂度合理，避免过长方法和过大类
- [ ] 资源正确关闭（数据库连接、文件流等）

## 3. 审查流程

### 3.1 本地开发
- [ ] 开发人员自测通过
- [ ] 本地运行所有相关测试用例
- [ ] 代码格式化符合规范
- [ ] 提交前运行自动化检查工具

### 3.2 代码提交
- [ ] 提交信息格式规范，包含相关任务编号
- [ ] 代码变更范围合理，不包含无关修改
- [ ] 分支命名规范
- [ ] 代码通过本地自动化检查

### 3.3 CI/CD
- [ ] 代码通过CI流水线所有检查
- [ ] 自动化测试全部通过
- [ ] 代码扫描无严重问题
- [ ] 构建成功

### 3.4 人工审查
- [ ] 至少一名团队成员进行代码审查
- [ ] 审查人员按照本清单逐项检查
- [ ] 发现的问题在合并前修复
- [ ] 审查通过后方可合并到主分支
