# 库存管理系统架构设计文档

## 1. 系统概述

### 1.1 系统简介
库存管理系统是一个基于微服务架构的模块化系统，用于管理商品目录、库存、订单、采购、销售等核心业务流程。系统采用Spring Cloud生态，支持高可用、可扩展的分布式部署。

### 1.2 系统目标
- 实现模块化的微服务架构，支持独立部署和扩展
- 提供统一的API接口，支持多客户端访问
- 实现高可用性和容错能力
- 支持实时监控和告警
- 提供灵活的配置管理
- 支持数据安全和访问控制

### 3.2 核心服务模块

#### 3.2.1 商品服务 (Product Service)
- 功能：管理商品目录、SKU、BOM等
- 主要接口：商品CRUD、SKU管理、BOM管理
- 依赖：PostgreSQL、Redis

#### 3.2.2 订单服务 (Order Service)
- 功能：处理订单创建、修改、查询、履行等
- 主要接口：订单CRUD、订单状态管理、订单履行
- 依赖：PostgreSQL、Redis、商品服务、库存服务

#### 3.2.3 库存服务 (Inventory Service)
- 功能：管理库存水平、库存移动、库存盘点等
- 主要接口：库存查询、库存更新、库存盘点
- 依赖：PostgreSQL、Redis

#### 3.2.4 销售服务 (Sales Service)
- 功能：处理销售订单、销售报表等
- 主要接口：销售订单管理、销售报表生成
- 依赖：PostgreSQL、Redis、订单服务

#### 3.2.5 采购服务 (Procurement Service)
- 功能：处理采购订单、采购计划等
- 主要接口：采购订单管理、采购计划生成
- 依赖：PostgreSQL、Redis、供应商服务

#### 3.2.6 客户服务 (Customer Service)
- 功能：管理客户信息、客户分类等
- 主要接口：客户CRUD、客户分类管理
- 依赖：PostgreSQL

#### 3.2.7 供应商服务 (Supplier Service)
- 功能：管理供应商信息、供应商分类等
- 主要接口：供应商CRUD、供应商分类管理
- 依赖：PostgreSQL

#### 3.2.8 认证服务 (Auth Service)
- 功能：处理用户认证、授权、令牌管理等
- 主要接口：登录、注册、令牌刷新、权限管理
- 依赖：PostgreSQL、Redis

#### 3.2.9 配置服务 (Config Service)
- 功能：管理系统配置、环境配置等
- 主要接口：配置CRUD、配置版本管理
- 依赖：Nacos Config

#### 3.2.10 API网关 (Gateway Service)
- 功能：处理API请求路由、负载均衡、安全认证等
- 主要接口：所有对外API接口的入口
- 依赖：Spring Cloud Gateway

### 3.3 共享模块

#### 3.3.1 公共模块 (Common)
- 功能：提供通用工具类、基础组件、统一异常处理等
- 主要组件：
  - ApiResponse：统一API响应格式
  - BusinessException：业务异常基类
  - GlobalExceptionHandler：全局异常处理器
  - Constants：常量定义
  - CustomCacheKeyGenerator：自定义缓存键生成器

## 4. 数据架构设计

### 4.1 数据库设计

#### 4.1.1 商品服务数据库
- 主要表：products、product_skus、boms、bom_components
- 关系：商品与SKU为一对多关系，商品与BOM为一对一关系，BOM与BOM组件为一对多关系

#### 4.1.2 订单服务数据库
- 主要表：orders、order_items、order_status_history
- 关系：订单与订单项为一对多关系，订单与订单状态历史为一对多关系

#### 4.1.3 库存服务数据库
- 主要表：inventory_levels、inventory_movements、inventory_audits
- 关系：库存水平与库存移动为一对多关系，库存水平与库存审计为一对多关系

### 4.2 缓存设计
- 使用Redis作为分布式缓存
- 缓存策略：
  - 商品信息缓存：30分钟
  - 库存水平缓存：5分钟
  - 订单信息缓存：10分钟
  - 用户会话缓存：30分钟

## 5. API设计

### 5.1 API设计原则
- 采用RESTful设计风格
- 使用统一的API响应格式
- 支持版本控制
- 实现权限控制
- 提供详细的API文档

### 5.2 API响应格式
```json
{
  "code": 200,
  "message": "Success",
  "data": {
    // 响应数据
  }
}
```

### 5.3 API版本控制
- 格式：/api/v{version}/{resource}
- 示例：/api/v1/products

## 6. 安全架构设计

### 6.1 认证机制
- 使用JWT进行身份认证
- 支持单点登录
- 实现令牌刷新机制

### 6.2 授权机制
- 基于角色的访问控制（RBAC）
- 细粒度的权限管理
- 支持动态权限分配

### 6.3 数据安全
- 数据库连接使用SSL加密
- 敏感数据加密存储
- 传输过程中数据加密

### 6.4 防攻击措施
- 实现API限流
- 防止SQL注入
- 防止XSS攻击
- 防止CSRF攻击
