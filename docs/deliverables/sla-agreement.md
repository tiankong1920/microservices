## 一、协议概述与适用范围

### 1.1 协议目的

本服务等级协议（Service Level Agreement，以下简称"SLA"）由乙方（服务提供方）与甲方（客户）共同签署，旨在明确乙方为甲方提供进销存管理系统 v3.0（以下简称"本系统"）服务时的质量标准、响应时效、问题处理流程及补偿机制，保障甲方业务的连续性与数据安全。

### 1.2 适用范围

本协议适用于以下服务内容：

- 进销存管理系统 v3.0 全部13个微服务模块：产品管理、库存管理、订单管理、采购管理、销售管理、客户管理、供应商管理、财务报表、认证鉴权、网关路由、服务注册、监控告警、模板服务
- 系统底层基础设施（应用服务器、数据库、缓存、消息队列）
- 数据备份与灾难恢复服务
- 技术支持与运维保障服务

### 1.3 适用客户类型

| 客户层级 | 部署模式 | SLA等级 |
|----------|----------|---------|
| 企业旗舰版 | 私有化部署 | 铂金级 |
| 企业专业版 | 公有云SaaS | 金级 |
| 企业标准版 | 公有云SaaS | 银级 |

> 本协议以金级SLA为基准，铂金级与银级的具体差异见各条款补充说明。

### 1.4 除外条款

以下情形不纳入SLA考核范围：

- 甲方自有网络或设备故障导致的服务不可达
- 甲方操作不当或违反使用规范导致的系统异常
- 不可抗力事件（自然灾害、战争、政府管制等）
- 计划内维护窗口期间的服务中断（详见第六章）
- 第三方服务依赖故障（如云服务商区域性宕机）

## 二、服务可用性承诺

### 2.1 可用性定义

服务可用性按月度计算，公式如下：

```
月度可用性 = (月度总分钟数 - 月度不可用分钟数) / 月度总分钟数 × 100%
```

**不可用分钟数**定义：系统连续5分钟以上无法正常响应有效请求的时间累计值。

### 2.2 可用性承诺

| 指标 | 金级（基准） | 铂金级 | 银级 |
|------|-------------|--------|------|
| 月度可用性 | ≥ 99.9% | ≥ 99.95% | ≥ 99.5% |
| 年度可用性 | ≥ 99.9% | ≥ 99.95% | ≥ 99.5% |
| 最大计划外停机时间（月） | ≤ 43.8分钟 | ≤ 21.9分钟 | ≤ 219分钟 |

### 2.3 可用性测量方式

- 通过独立监控系统（Prometheus + Grafana）从多地域探测节点进行5分钟间隔健康检查
- 以HTTP状态码2xx/3xx为可用判定标准，超时阈值10秒
- 甲方可通过管理后台查看实时可用性仪表盘
- 月度可用性报告于次月第3个工作日前提交甲方

### 2.4 计划内维护窗口

| 维护类型 | 时间窗口 | 提前通知 | 影响时长 |
|----------|----------|----------|----------|
| 常规维护 | 每周六 02:00-06:00 | 3个工作日 | ≤ 2小时 |
| 紧急补丁 | 协商确定 | 尽最大努力 | ≤ 30分钟 |
| 重大升级 | 协商确定 | 15个工作日 | ≤ 4小时 |

> 计划内维护窗口内的服务中断不计入不可用时间。

## 三、响应时间与处理时效

### 3.1 问题分级标准

| 级别 | 名称 | 定义 | 典型场景 |
|------|------|------|----------|
| P0 | 紧急 | 系统全面不可用，核心业务流程完全中断 | 全站宕机、数据库崩溃、数据大面积丢失 |
| P1 | 高 | 核心功能严重受损，业务运行受到重大影响但未完全中断 | 订单无法创建、库存数据不同步、财务报表无法生成 |
| P2 | 中 | 非核心功能异常或核心功能轻微受损，存在临时绕行方案 | 报表导出失败、搜索响应缓慢、单个模块异常 |
| P3 | 低 | 界面瑕疵、优化建议或功能咨询，不影响业务运行 | 界面文字错误、操作体验建议、功能使用咨询 |

### 3.2 响应与处理时效

| 级别 | 首次响应时间 | 处理方案提供 | 修复完成 | 事后报告 |
|------|-------------|-------------|----------|----------|
| **P0 紧急** | ≤ 15分钟 | ≤ 2小时 | ≤ 4小时 | 24小时内 |
| **P1 高** | ≤ 30分钟 | ≤ 4小时 | ≤ 8小时 | 48小时内 |
| **P2 中** | ≤ 2小时 | ≤ 8小时 | ≤ 24小时 | 3个工作日内 |
| **P3 低** | ≤ 4小时 | ≤ 2个工作日 | ≤ 5个工作日 | 5个工作日内 |

> **铂金级**：P0首次响应时间 ≤ 10分钟，修复完成 ≤ 2小时。  
> **银级**：P0首次响应时间 ≤ 30分钟，修复完成 ≤ 8小时。

### 3.3 时效计算规则

- **工作时间**：周一至周五 09:00-18:00（法定节假日除外）
- **P0/P1级别**：7×24小时全天候响应，时效从问题确认时刻起计
- **P2/P3级别**：仅工作时间计算时效，非工作时间提交的问题顺延至下一工作日9:00起计
- **首次响应**：乙方工程师确认收到问题并开始处理的时刻

## 四、问题处理流程

### 4.1 流程总览

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  问题受理  │───▶│  问题诊断  │───▶│  修复实施  │───▶│  验证确认  │───▶│  工单关闭  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
     │               │               │               │               │
     ▼               ▼               ▼               ▼               ▼
  接收&分级       根因分析       代码修复/       甲方确认         归档&复盘
  分配工程师     影响范围评估     配置变更/       功能恢复                    回归测试       问题归因
                                 数据修复
```

### 4.2 各阶段详细说明

#### 4.2.1 问题受理

- 甲方通过支持渠道提交问题工单
- 乙方值班工程师在响应时效内确认接收
- 根据问题描述进行初步分级（P0-P3）
- 指派对应级别工程师负责跟踪
- 如分级存在争议，默认按高级别处理，后续可调整

#### 4.2.2 问题诊断

- 负责工程师进行问题复现与根因分析
- 涉及P0/P1级别时，启动紧急响应小组（至少3名高级工程师）
- 输出诊断报告：问题根因、影响范围、临时缓解措施
- 与甲方沟通确认诊断结论

#### 4.2.3 修复实施

- 制定修复方案，P0/P1级别需技术负责人审批
- 实施代码修复、配置变更或数据修复
- 修复部署遵循CI/CD流水线（Jenkins + GitHub Actions）
- P0级别修复经紧急审批通道，可在常规窗口外部署
- P1及以下级别修复原则上在下一维护窗口内部署

#### 4.2.4 验证确认

- 乙方内部验证修复效果与回归测试
- 通知甲方进行业务验证
- 甲方确认问题已解决后进入关闭环节
- 如甲方3个工作日内未反馈，视为默认确认

#### 4.2.5 工单关闭

- 工单状态变更为"已关闭"
- 归档问题处理全流程记录
- P0/P1级别须在规定时效内提交事后分析报告（RCA）
- 报告内容包含：根因分析、修复措施、预防方案

### 4.3 问题升级机制

| 触发条件 | 升级动作 | 责任人 |
|----------|----------|--------|
| P0问题2小时内无修复方案 | 升级至技术总监 | 技术总监 |
| P1问题4小时内无修复方案 | 升级至技术经理 | 技术经理 |
| P2问题24小时内无修复方案 | 升级至高级工程师 | 技术经理 |
| 甲方对处理结果不满意 | 升级至客户成功经理 | 客户成功负责人 |

## 五、数据安全与隐私承诺

### 5.1 数据加密

| 安全层面 | 技术措施 | 标准依据 |
|----------|----------|----------|
| 传输加密 | TLS 1.3 协议，全站HTTPS | RFC 8446 |
| 存储加密（密码） | BCrypt自适应哈希算法，cost factor ≥ 12 | OWASP推荐 |
| 存储加密（敏感数据） | AES-256-GCM 对称加密 | NIST SP 800-38D |
| 数据库加密 | 透明数据加密（TDE） | PCI DSS 3.2.1 |
| 备份加密 | AES-256加密存储，异地容灾 | ISO 27001 |

### 5.2 访问控制

- 基于RBAC（基于角色的访问控制）模型，细粒度权限管理
- 认证鉴权服务独立微服务，OAuth 2.0 + JWT令牌机制
- API网关统一鉴权，所有请求强制身份认证
- 敏感操作强制二次验证（MFA）
- 管理员操作实时审计记录

### 5.3 审计日志

| 日志类型 | 记录内容 | 保留期限 |
|----------|----------|----------|
| 操作审计 | 用户ID、操作类型、操作对象、操作时间、IP地址 | ≥ 180天 |
| 系统审计 | 服务启停、配置变更、部署记录 | ≥ 365天 |
| 安全审计 | 登录尝试、权限变更、数据导出 | ≥ 365天 |
| 数据审计 | 敏感数据访问、修改、删除记录 | ≥ 365天 |

### 5.4 数据备份与灾难恢复

| 指标 | 承诺标准 |
|------|----------|
| 备份频率 | 全量备份每日1次，增量备份每4小时1次 |
| 备份保留 | 全量备份保留30天，增量备份保留7天 |
| 恢复点目标（RPO） | ≤ 4小时 |
| 恢复时间目标（RTO） | ≤ 2小时（铂金级 ≤ 1小时） |
| 备份验证 | 每月1次恢复演练 |
| 异地容灾 | 主备双活架构，跨可用区部署 |

### 5.5 隐私保护承诺

- 严格遵守《中华人民共和国个人信息保护法》及《数据安全法》
- 不采集与服务无关的用户数据
- 不向第三方出售、共享甲方业务数据
- 甲方数据可随时导出，服务终止后30日内彻底删除乙方系统中的甲方数据
- 接受甲方指定的第三方安全审计（年度1次，费用由甲方承担）

## 六、服务变更通知机制

### 6.1 变更分类

| 变更类型 | 定义 | 通知提前量 | 通知方式 |
|----------|------|-----------|----------|
| 重大变更 | 影响系统功能、界面、工作流的变更 | ≥ 15个工作日 | 书面通知（邮件+站内信） |
| 一般变更 | 新增功能模块、接口版本升级 | ≥ 10个工作日 | 邮件通知 |
| 轻微变更 | Bug修复、性能优化、界面微调 | ≥ 3个工作日 | 站内通知 |
| 紧急变更 | 安全漏洞修复、数据安全风险处置 | 尽最大努力提前通知 | 邮件+短信+站内信 |

### 6.2 通知内容

每份变更通知须包含：

1. 变更内容描述
2. 变更原因说明
3. 预期影响范围与时长
4. 实施时间窗口
5. 甲方需配合的事项（如有）
6. 回滚方案说明
7. 联系人与反馈渠道

### 6.3 变更协商

- 重大变更：甲方可在收到通知后5个工作日内提出异议，双方协商调整
- 如协商未果，甲方有权选择不接受变更，乙方需维持原版本服务至少30日过渡期
- 安全紧急变更不受协商限制，但须在变更后24小时内补充书面说明

## 七、补偿条款

### 7.1 可用性不达标补偿

当月度服务可用性未达到承诺标准时，甲方有权申请服务费用减免：

| 月度可用性 | 金级补偿比例 | 铂金级补偿比例 | 银级补偿比例 |
|-----------|-------------|---------------|-------------|
| < 99.9% 但 ≥ 99.0% | 月度服务费5% | 月度服务费8% | — |
| < 99.0% 但 ≥ 95.0% | 月度服务费15% | 月度服务费20% | 月度服务费5% |
| < 95.0% 但 ≥ 90.0% | 月度服务费30% | 月度服务费40% | 月度服务费15% |
| < 90.0% | 月度服务费50% | 月度服务费70% | 月度服务费30% |

### 7.2 响应时效不达标补偿

| 违约情形 | 补偿标准 |
|----------|----------|
| P0首次响应超时 | 当月服务费2% |
| P0修复完成超时 | 当月服务费5% |
| P1首次响应超时 | 当月服务费1% |
| P1修复完成超时 | 当月服务费3% |
| 同一P0问题30天内复发 | 当月服务费10% |

### 7.3 补偿申请流程

1. 甲方在收到月度服务报告后10个工作日内提交补偿申请
2. 乙方在5个工作日内完成审核与确认
3. 补偿金额从下一期服务费中直接抵扣
4. 甲方未在规定期限内提出申请，视为放弃当月补偿权利

### 7.4 补偿上限

- 单月补偿金额不超过当月服务费的50%
- 年度累计补偿金额不超过年度服务费总额的30%
- 补偿为甲方唯一且排他的救济方式，不包含间接损失、利润损失等

## 八、协议有效期与续约

### 8.1 协议期限

- 本协议有效期为一个自然年，自签署之日起生效
- 首期协议起止日期以合同约定为准

### 8.2 自动续约

- 协议到期前30日，如双方均未提出终止书面通知，本协议自动续约一年
- 续约后的条款与费率以乙方届时公布的最新版本为准
- 如乙方调整费率，须在续约生效前15日书面通知甲方

### 8.3 协议终止

| 终止情形 | 通知期限 | 数据处理 |
|----------|----------|----------|
| 甲方主动终止 | 提前30日书面通知 | 30日内完成数据导出与删除 |
| 乙方主动终止 | 提前90日书面通知 | 协助甲方完成数据迁移 |
| 违约终止 | 依据违约条款执行 | 按数据安全条款执行 |
| 不可抗力终止 | 即时通知 | 尽最大努力保障数据安全 |

### 8.4 SLA版本更新

- 乙方有权根据技术演进与服务能力提升更新SLA条款
- 更新后的SLA不得降低甲方现有服务标准
- SLA更新通知与一般变更通知机制一致
