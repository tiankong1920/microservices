## 1. 项目概述与背景

### 1.1 项目立项背景

随着企业数字化转型的深入推进，中小型企业对高效、灵活的库存管理系统的需求日益迫切。传统的ERP系统往往价格高昂、部署复杂、维护成本高，难以满足成长型企业的快速迭代需求。库存管理系统v3.0旨在构建一套轻量化、可扩展、高性价比的企业级库存管理解决方案，支持采购、销售、订单、库存等全链路业务流程，帮助企业实现库存可视化、流程自动化、决策数据化。

### 1.2 市场环境分析

**市场规模与增长趋势：**

- 全球企业库存管理软件市场预计到2027年将达到58亿美元，年复合增长率(CAGR)约7.2%
- 中国企业级SaaS市场持续增长，库存管理和供应链数字化是企业数字化转型的核心环节
- 电商、零售、制造业对实时库存管理的需求快速增长，尤其在多渠道销售场景下

**目标用户群体特征：**

| 用户类型 | 规模特征 | 技术能力 | 核心诉求 |
|----------|----------|----------|----------|
| 中小型零售商 | 年营业额500万-5000万 | IT能力较弱 | 易用、快速上手、移动端支持 |
| 贸易批发商 | 年营业额1000万-2亿 | 具备基础IT能力 | 多仓库管理、批次管理、报表分析 |
| 制造业企业 | 年营业额5000万以上 | 具备一定IT能力 | 生产配料管理、供应商协同、质量追溯 |
| 连锁经营企业 | 多门店/多仓库 | IT能力较强 | 统一库存分配、店间调拨、实时同步 |

### 1.3 现有解决方案的局限性

经过对市场上主流库存管理产品的调研分析，现有解决方案存在以下不足：

| 维度 | 现有产品问题 | 具体表现 |
|------|--------------|----------|
| **功能层面** | 功能僵化，难以定制 | 无法适应特殊业务流程，定制开发周期长、成本高 |
| **性能层面** | 并发处理能力不足 | 促销活动高峰期系统响应缓慢，甚至宕机 |
| **用户体验** | 界面复杂，学习成本高 | 员工培训周期长，操作效率低，错误率高 |
| **集成能力** | 开放性不足 | 与财务系统、电商平台、物流服务的集成能力弱 |
| **数据安全** | 权限管理粗粒度 | 无法实现细粒度的数据权限控制，存在数据泄露风险 |
| **移动化** | 移动端体验差 | 移动端功能残缺，无法满足外勤、仓库等场景需求 |

### 1.4 项目意义及预期解决的核心问题

**核心问题优先级划分：**

| 优先级 | 问题描述 | 影响范围 | 预期解决效果 |
|--------|----------|----------|--------------|
| **P0** | 库存数据不准确，导致缺货或积压 | 所有业务环节 | 实现库存实时同步，账实一致率≥99.5% |
| **P1** | 订单处理效率低，客户体验差 | 销售、客服 | 订单处理时间缩短60%，客户满意度提升 |
| **P2** | 跨部门协同成本高，信息孤岛 | 采购、仓库、销售 | 信息流转效率提升80%，减少沟通成本 |
| **P2** | 缺乏数据支撑，决策困难 | 管理层 | 提供多维度数据分析报表，辅助科学决策 |
| **P3** | 系统可扩展性不足 | IT部门 | 微服务架构，支持按需扩展、敏捷迭代 |

## 4. 功能需求

### 4.1 核心功能模块

#### 4.1.1 基础数据管理模块

| 项目 | 描述 |
|------|------|
| **功能定义** | 提供商品、客户、供应商、仓库等基础数据的增删改查管理 |
| **业务规则** | - 商品编码唯一，支持条码管理<br>- 客户/供应商支持分类分级管理<br>- 仓库支持多仓库、多仓位管理<br>- 数据支持批量导入导出 |
| **用户操作流程** | 新建商品：基本信息→价格策略→库存设置→ Warehouse Assignment → 保存审核 |
| **输入输出要求** | 商品编码(20字符)、名称(100字符)、规格(50字符)、单位(10字符)、条形码(30字符)、含税售价(decimal,2位小数)、最低库存(整数)、最高库存(整数) |
| **优先级** | **P0** |

**主要功能点：**

1. **商品管理**
   - 商品档案：基本信息、价格、库存参数、图片、附件
   - 商品分类：多级分类树，支持分类属性模板
   - 商品条码：支持一品多码，支持条码打印
   - 组合商品：支持套装、捆绑销售配置

2. **客户管理**
   - 客户档案：基本信息、联系方式、地址、银行账户
   - 客户分级：VIP/普通/潜在，支持分级价格策略
   - 信用管理：信用额度、信用账期、超额审批
   - 客户分析：交易历史、贡献度、流失预警

3. **供应商管理**
   - 供应商档案：基本信息、联系方式、资质证照
   - 供应商评级：质量/交期/价格多维度评分
   - 采购协议：采购价格、账期、返利政策

4. **仓库管理**
   - 仓库档案：仓库信息、负责人、联系方式
   - 仓位管理：多级仓位(区→排→层→位)
   - 库位视图：可视化仓位图，支持快速定位

#### 4.1.2 采购管理模块

| 项目 | 描述 |
|------|------|
| **功能定义** | 采购订单的创建、审批、执行、收货、入库全流程管理 |
| **业务规则** | - 采购订单需审批（金额阈值）<br>- 支持分批收货<br>- 到货验收不合格可退货<br>- 采购入库自动更新库存和财务数据 |
| **用户操作流程** | 采购申请→采购订单→审批→供应商发货→到货验收→入库上架 |
| **输入输出要求** | 订单编号(系统生成)、供应商ID、付款方式(现结/账期)、交货日期、收货仓库、商品明细(商品ID+数量+单价+金额) |
| **优先级** | **P0** |

**主要功能点：**

1. **采购申请**
   - 根据库存预警自动生成采购建议
   - 支持手工创建采购申请
   - 采购申请可合并生成采购订单

2. **采购订单**
   - 订单创建、修改、取消
   - 多级审批流程（按金额区间）
   - 订单执行跟踪（已发货/已到货/已完成）

3. **采购收货**
   - 到货扫码验收
   - 不良品登记与退货处理
   - 收货数量与订单对比分析

4. **采购入库**
   - 扫码入库确认
   - 自动更新库存数量

## 6. 产品交互流程

### 6.1 用户注册登录流程

```
┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│  打开   │────▶│  输入   │────▶│  验证   │────▶│  设置   │────▶│  登录   │
│  APP    │     │ 手机号  │     │ 验证码  │     │  密码   │     │  成功   │
└─────────┘     └─────────┘     └─────────┘     └─────────┘     └─────────┘
                                                                      │
                                         ┌───────────────────────────┘
                                         │ 失败
                                         ▼
                                   ┌───────────┐
                                   │ 错误提示  │──▶ 返回重新输入
                                   └───────────┘
```

**步骤说明：**

1. 用户打开APP/网页，进入登录页
2. 输入手机号，点击获取验证码
3. 输入收到的短信验证码（5分钟内有效）
4. 验证通过后设置登录密码（8-20位，含字母和数字）
5. 注册成功，自动登录进入首页
6. 登录失败显示错误提示

### 6.2 采购入库流程

```
┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐
│ 供应商发货 │──▶│ 到货登记  │──▶│ 扫码验收  │──▶│ 确认入库  │──▶│ 完成入库  │
└───────────┘   └───────────┘   └───────────┘   └───────────┘   └───────────┘
                                                                    │
                                                            ┌───────▼───────┐
                                                            │ 更新库存台账  │
                                                            │ 生成入库单    │
                                                            │ 通知相关人员  │
                                                            └───────────────┘
```

**步骤说明：**

1. 供应商发货后，采购员在系统中登记到货信息
2. 货物到达仓库，收货员扫码采购单据
3. 逐件扫描商品条码，系统显示应收数量
4. 验收无误后确认入库，系统自动：
   - 更新库存台账（增加库存数量）
   - 生成正式入库单
   - 更新采购订单状态
   - 通知采购主管和销售部门

**异常处理：**

- 商品不符：扫码不符时报警声提示，可选择拒收或部分收货
- 数量差异：到货数量与订单不符时，系统记录差异并通知采购员
- 品质异常：不良品单独登记，转入退货处理流程

### 6.3 销售订单处理流程

```
┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐
│ 询价报价  │──▶│ 创建订单  │──▶│ 审批确认  │──▶│ 库存预留  │──▶│ 仓库拣货  │
└───────────┘   └───────────┘   └───────────┘   └───────────┘   └───────────┘
                                                                    │
┌───────────┐   ┌───────────┐   ┌───────────┐                     │
│ 客户收货  │◀──│ 出库发货  │◀──│ 扫码出库  │◀─────────────────────┘
└───────────┘   └───────────┘   └───────────┘
                       │
               ┌───────▼───────┐
               │ 更新库存台账  │
               │ 生成销售单    │
               │ 更新订单状态  │
               └───────────────┘
```

**步骤说明：**

1. 客户询价，销售员快速查询库存并报价
2. 客户确认后创建销售订单
3. 订单根据金额/客户信用等规则进入审批流程
4. 审批通过后自动预留库存
5. 仓库收到拣货任务，扫码拣货
6. 打包完成后扫码出库
7. 系统更新库存台账，生成销售单，更新订单状态为"已发货"
8. 客户确认收货（或系统自动确认）

**异常处理：**

- 库存不足：提示可分配数量，支持部分发货或缺货预订
- 订单变更：已审批订单变更需重新审批，涉及金额变化走差异审批
- 客户拒收：录入拒收原因，转入退货退款流程

### 6.4 库存盘点流程

```
┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐
│ 创建盘点  │──▶│ 打印盘点  │──▶│ 现场盘点  │──▶│ 录入实盘  │──▶│ 审核差异  │
│ 计划单    │   │ 清单      │   │ 扫码      │   │ 数据      │   │ 确认调整  │
└───────────┘   └───────────┘   └───────────┘   └───────────┘   └───────────┘
                                                                    │
                                                            ┌───────▼───────┐
                                                            │ 生成库存调整  │
                                                            │ 单并执行      │
                                                            │ 更新库存台账  │
                                                            └───────────────┘
```

**步骤说明：**

1. 仓库主管创建盘点计划，选择仓库/品类/时间段
2. 系统生成盘点清单，打印或导出
3. 盘点员到仓库现场，扫描商品条码
4. 输入实际盘点数量
5. 盘点完成提交，系统自动计算差异
6. 仓库主管审核差异，确认调整
7. 系统生成库存调整单，执行调整，更新库存台账

**异常处理：**

- 扫码商品不在盘点单：提示并可选择"新增盘点项"
- 盘点数量与系统差异大：要求录入备注说明，必要时拍照留证
- 盘点期间禁止相关出入库操作（或记录隔离）

| 操作 | 触发条件 | 处理逻辑 |

| 库存减少 | 销售出库、采购退料、库存盘亏、调拨出库 | UPDATE库存台账，日志记录，出具出库单 |

| 库存释放 | 订单取消、超时未支付 | UPDATE available_quantity增加，allocated_quantity减少 |
| 成本计算 | 入库时 | 采用加权平均法：成本 = (现有库存金额 + 新入库金额) / (现有数量 + 新入库数量) |

### 10.1 风险识别与评估

### 10.2 重点风险应对策略

#### R001：需求变更频繁

**预防措施：**

- 需求冻结机制：需求评审通过后，变更需走变更评审流程
- 敏捷迭代：采用敏捷方法，每2周一个Sprint，可快速响应
- MVP策略：优先交付核心功能，减少不确定性

**应对方案：**
- 评估变更影响范围，与客户/干系人沟通调整计划
- 必要时调整迭代计划或延期交付

**责任人：** 产品经理

#### R002：技术架构调整

**预防措施：**

- 技术方案评审：架构设计需通过技术评审
- POC验证：新技术点需先POC验证可行性
- 代码审查：严格执行代码审查，避免架构腐化

**应对方案：**
- 组织技术攻关小组
- 评估是否需要外部技术支持
- 必要时调整架构或技术选型

**责任人：** 架构师

#### R003：核心开发人员离职

**预防措施：**

- 知识共享：Code Review + 文档记录
- 任务分配：避免1人负责核心模块
- 激励机制：合理的激励措施

**应对方案：**

- 提前规划交接
- 紧急招聘补充
- 调整任务分配

**责任人：** 技术负责人

#### R005：性能测试未达标

**预防措施：**

- 性能意识：开发阶段即考虑性能
- 早期测试：集成测试阶段即进行性能测试
- 代码规范：避免N+1查询等性能杀手

**应对方案：**

- 性能分析和优化
- 架构优化（缓存、异步等）
- 必要时硬件扩容

**责任人：** 性能工程师

#### R006：数据迁移风险

**预防措施：**

- 数据清洗：迁移前进行数据质量检查
- 多次演练：UAT环境多次迁移演练
- 回滚方案：制定完整回滚方案

**应对方案：**

- 启动回滚
- 数据修复
- 增量补录

**责任人：** DBA + 运维

#### R008：安全漏洞

**预防措施：**

- 安全编码：开发人员安全培训
- 安全扫描：代码提交前SAST扫描
- 渗透测试：上线前专业渗透测试

**应对方案：**

- 紧急修复漏洞
- 评估影响范围
- 通知受影响的用户（如有）

**责任人：** 安全工程师
